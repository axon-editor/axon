## Axon v1.3.8

Axon v1.3.8 is a security, language intelligence, and multi-window reliability
release. It preserves richer syntax identities through theme resolution,
repairs managed language-tool installation, hardens every renderer-to-main
workspace boundary, and makes background work belong to the window that
started it. It also completes the terminal theme and packaged-host lifecycle
work, restores editor font selection, improves breadcrumbs and hover geometry,
and removes every high-severity application dependency finding.

### Syntax coloring and language tools

- TextMate captures and language-server legends now retain named token identity
  through the final merge instead of collapsing into fixed numeric categories.
- Authored theme captures and Axon fallback captures resolve as separate layers,
  preserving the theme author's intended colors, typography, and inheritance.
- Token inspection exposes the original TextMate scopes and source captures so
  theme behavior can be diagnosed against the actual grammar output.
- Optional TextMate enrichment catches malformed grammars and timeouts, then
  falls back to Monaco and LSP coloring without rejecting the whole request.
- Small files receive enough grammar-tokenization time under build contention,
  while larger documents retain the stricter responsiveness budget.
- Makefile language tools use the compatible tree-sitter API, and staged Python
  installations must pass an import check before replacing a working runtime.
- Stalled tool downloads time out and retry once from a clean, checksum-verified
  destination instead of freezing partway through C or C++ installation.

### Security and window ownership

- Renderer-scoped capabilities now protect Git, LSP, AI, diagnostics, tasks,
  tests, previews, extensions, watchers, and filesystem IPC operations.
- Media, Markdown assets, backgrounds, and custom fonts use expiring opaque
  tickets rather than exposing local filesystem paths to renderer content.
- LSP edits are validated before they can write outside the renderer's granted
  workspace, and external worktree paths require trusted native selection.
- Tasks, tests, previews, updates, services, and account events are routed only
  to their owning window, with child processes stopped when that window closes.
- HTML previews use authenticated loopback targets, per-server tokens, and
  strict cookies rather than relying on an unprotected local endpoint.
- Workspace layouts persist under independent main-process window identities and
  restore the most recently active session without reviving stale ownership.

### Terminal and application lifecycle

- Running xterm sessions receive complete ANSI, cursor, selection, scrollbar,
  and overview-ruler palettes when the active theme changes.
- Focus-aware terminal applications refresh after xterm installs the new palette,
  without injecting compatibility sequences into ordinary shells.
- Packaged PTY hosts are tied to Electron through an operating-system ownership
  pipe and cannot silently remain alive after their parent disappears.
- Replaced or unreachable control sockets are authenticated and rebound without
  terminating live terminal streams or destroying PTY sessions.
- Graceful process shutdown waits for actual child exit, escalates stuck bundled
  services within bounded waits, and preserves state when death is unconfirmed.
- Private service credentials and transport addresses no longer leak into child
  shell environments, and PTY diagnostics rotate with private permissions.

### Editor and workspace behavior

- Fira Code and JetBrains Mono ship as usable editor presets, while custom font
  choices remain intact instead of being rewritten to Axon Mono.
- Known binary formats such as XLSX open in a dedicated read-only preview and Git
  reports them as binary changes without decoding blob contents as UTF-8.
- Breadcrumbs occupy their own row above Monaco, making their lower edge the true
  top of the gutter, text viewport, and editor widget geometry.
- Hover placement is configurable as Top or Bottom, with Top remaining the safe
  default and Monaco choosing the final in-viewport position near boundaries.
- Open Folder replaces the ordinary single workspace root, while restored
  multi-root sessions remain supported and recent folders show their live state.
- Native macOS fullscreen removes the absent traffic-light inset and restores it
  when leaving fullscreen, independently for every Axon window.
- The macOS application mark has been optically reduced within its existing
  canvas so its Dock weight matches surrounding applications.

### Release, packaging, and maintenance

- Electron, Monaco, Mermaid, DOMPurify, electron-builder, electron-updater, and
  archive dependencies were upgraded to remove all high-severity audit findings.
- JavaScript language servers remain inside `app.asar`; only native bindings are
  unpacked, reducing generated unpacked resources to 21 files and about 22 MB.
- Packaging verification covers 614 language-server dependency patterns and
  executes TypeScript Language Server directly from the assembled application.
- Release tags must match the root manifest, editor manifest, lockfile workspace
  records, and a corresponding release-notes document before publication.
- Windows in-app updates require signature verification, and macOS Intel and
  Apple Silicon metadata are merged into one architecture-aware update record.
- Workbench lifecycle hooks now observe current state with deterministic timer
  cleanup, and the application view contract no longer accepts arbitrary values.
