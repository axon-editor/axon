## Axon v4.3.0

Axon v4.3.0 is a coloring, language-server, testing, and Git reliability
release. It fixes the token pipeline so imported themes color the code they
were written for, gives every installed language server hover and completion
coverage, teaches the Test Explorer Django and pytest layouts, and stops
transient Git failures or restored windows from hiding Source Control. It also
includes the full-screen terminal agent TUI, managed OpenCode, and the security
and dependency work merged since v4.2.0.

### Code coloring and language servers

- Language-tagged capture candidates resolve to their real capture instead of a
  truncated parent, restoring parameter, method, class, interface, builtin, and
  macro colors.
- Exact theme captures now win over inherited parents, so HTML and JSX
  attributes reach the authored `attribute` capture instead of the tag color.
- Member access is limited to identifier-like tokens, preventing characters
  inside strings, numbers, and dotenv values from turning into properties or
  method calls.
- Dotenv files use a dedicated language path with property keys, string values,
  numeric and boolean scalars, comments, and `${VAR}` interpolation.
- TypeScript class, interface, enum, and struct scopes classify separately, the
  `new` keyword produces constructor captures, and CSS properties and selectors
  reach their own captures.
- Shiki failures no longer poison the shared engine for the session, and the
  code snapshot exporter respects authored font weight and 8-digit colors.
- Every Monaco language in the shared language-server table now registers
  hover, definition, reference, rename, format, signature help, code action, and
  completion providers, covering Swift, Ruby, Dart, SQL, TOML, Zig, Terraform,
  LaTeX, Scala, Clojure, Haskell, Erlang, R, PowerShell, Assembly, and Makefile.
- Python selects the detected project interpreter for Pyright and uses the same
  discovery for test runs.

### Testing

- The Test Explorer recognizes Django `manage.py` projects and discovers
  `tests.py` files alongside `test_*.py` and `*_test.py`.
- Pytest is selected only when the project configures it, and unrelated
  `pyproject.toml` files no longer force a pytest provider.
- Discovered test targets map to dotted Django module labels, while pytest runs
  use the project virtual environment when one exists.
- Open explorers auto-refresh when test files or project markers are created,
  deleted, or renamed, without collapsing providers or losing the selected
  target.

### Git and workspace capabilities

- Read-only Git commands disable optional locks, so concurrent windows cannot
  fail `git status` on an index-lock race.
- A failed status scan retries once and keeps the repository root and branch
  instead of reporting "not a repository".
- Refresh failures keep the previous status, so buttons, branch text, and line
  paint do not disappear after a transient error.
- Workspace open retries Git discovery and writes the real error to the Git
  output channel when it still fails.
- Every restored workspace root is re-authorized for the renderer that owns the
  window, so Git, tests, and terminals work in second windows and multi-root
  sessions.

### Workbench and developer workflow

- The file tree context menu and the workspace trust dialog are portaled above
  the workbench regions, restoring click handling and glass styling.
- `npm run dev` preflights ports 17777, 17778, and 5173, reclaiming listeners
  whose parent process is gone while refusing to kill a live session.
- Semantic-token, language-registration, LSP-definition, shared-language, and
  Git-status code moved into capability folders.
- The dedicated Settings window is scoped to the active workspace, markdown
  previews render raw HTML images inline, and release-note group labels stay
  outside commit lists.
- Native glass repaints after the first frame, and Live Glass is exposed only
  on Windows.

### Terminal agent and OpenCode

- A full-screen terminal agent TUI replaces the inline legacy CLI, with a
  capability-split app and an Axon circuit-frame input.
- The TUI supports model picking, thinking blocks, thought navigation,
  expandable reasoning, styled markdown transcripts, persistent tool cards, and
  command approvals.
- Conversations persist in a shared SQLite session store used by both the
  terminal and the editor, including imported sidebar conversations and tool
  history.
- Searchable session navigation, fuzzy slash matching, filtered command
  arguments, exact model arguments, command aliases, copy selection, and mouse
  scrolling round out the terminal workflow.
- Managed OpenCode is available as an agent backend, with isolated sessions,
  install and account detection, persisted model turns, and provider-grouped
  model pickers in the agent sidebar.
- Agent UI actions route through workbench tools, transcripts render
  consistently, and finished tool cards compact while streams stay scrollable.

### Security and dependencies

- Workspace path handling is hardened and CodeQL findings are cleared.
- Vulnerable dependencies are updated and Markdown HTML is sanitized.
- The language-server package lockfile stays in sync with release packaging.
