## Axon v4.1.0

Axon v4.1.0 is an agent and performance release. Axon Agent becomes a
tool-driven assistant that plans workbench actions, reads problems and files,
and runs its edits only after you approve them, while the sidebar reports which
local models this machine can actually run. Large documents and lockfiles open
through a reduced path that skips the expensive language features, every modal
panel scales with the window and resizes by drag, and the ghost frames that
stacked behind native glass popups are gone.

### Axon Agent tool loop

- The agent plans its own workbench actions with model tool calls: a shared UI
  tool catalog maps model tools onto the workbench commands the agent can
  drive, and the loop runs in the Electron main process.
- Proposed UI actions arrive as cards in the agent sidebar and run only after
  you approve them, so the agent proposes while you keep the trigger.
- A workbench UI-state snapshot is threaded into the prompt so the actions are
  grounded in what is on screen.
- Running tool calls stream into the card with their arguments, and each result
  comes back as a truncated preview in an expandable block, so searches and
  problem queries are visible instead of inferred.
- A `list_problems` tool reads every Problems panel diagnostic across the
  workspace with severity and path filters, and `fix-problem` calls it before
  choosing a fix.
- `close_active_tab` and `close_file` let the agent close any open tab,
  including the problems tab, by resolving URI-style tab paths instead of
  treating them as workspace-relative.
- An `agent` action joins the editor defaults as the tool-driven mode, leaving
  the CLI's read-only `ask` action untouched.

### Agent speed and context

- The local runtime keeps the model warm between turns with `keep_alive`, so
  turns no longer pay an unload and reload.
- The autonomous agent runs on a small context of paths, on-screen state, and a
  diagnostics summary, and reads files and problems with tools when it needs
  more, while deterministic actions keep the full file and git context.
- `num_ctx` is raised to 16384 so Ollama stops falling back to its 4096-token
  default and dropping the tool schemas once the conversation grows, and
  conversation history is bounded so it cannot crowd the tools out of the
  window.
- The agent is told to call the workbench tools instead of explaining them.

### Ask Axon sidebar and model fit

- Axon-core detects host memory and OS once, and every AI surface shares the
  result to compute model compatibility.
- The catalog grows to nine models ordered by footprint with minimum and
  recommended memory, and the models API reports compatibility as great, ok, or
  unsupported alongside the memory fields.
- Settings hides models that need more memory behind a show-all toggle, the
  sidebar flags tight or unsupported models, and the host default is the most
  capable model that runs comfortably.
- The real Axon mark replaces the lettered avatars in the header and empty
  state, and assistant messages drop the avatar.
- A shared `usePopoverDismiss` hook and popup enter animations cover every
  sidebar popup and the clear-conversation modal, and the installed-model
  dropdown no longer flashes while it refreshes.
- "New conversation" reuses and prunes empty threads instead of stacking
  duplicates, and is disabled while the active thread is blank.

### Large and lockfile documents

- A three-tier document policy (full, reduced, plain) in the shared
  large-document module decides how much language machinery a file earns.
- Lockfiles (`package-lock.json`, `bun.lock`, and the other known names) are
  detected and forced to plain language regardless of size.
- The plain path is routed through buffer creation and model-language refresh
  for both hard-tier and lockfile files, so those documents skip the language
  features instead of stalling on them.
- The semantic token overlay, Shiki decorations, and AI inline completions are
  guarded against reduced-tier models, and grammar preload plus LSP warm IPC
  are skipped for lockfile buffers.

### Modal panels

- Every modal panel moves from a fixed width to a `vw`-clamped size, so panels
  track the window instead of staying pinned at one pixel width.
- The heavy drop shadows behind modal panels are gone, along with the
  `axon-git-modal-panel` box-shadow rule.
- A `useResizablePanel` hook adds a corner drag handle to the diff, source
  control, extensions, test explorer, workspace search, and folder picker
  panels: sizes clamp to the viewport, persist per modal in localStorage, and
  reset on double-click or Escape, with arrow keys resizing a focused handle.
- `CommandModal` takes an opt-in `resizable` id, and the hook covers drag,
  persistence, clamping, reset, and Escape handling with tests.

### Native glass and window chrome

- Ghost-frame stacking behind native glass popups ends by painting the window
  root at the existing 0.01 glass alpha instead of fully transparent, so
  Chromium never composites a damaged rect against a stale vibrancy snapshot.
- The floating-surface repaint observer and the workspace-switch pulse are
  removed: both flashed visibly and only covered part of the surface. An
  earlier attempt had retargeted that pulse at the body so portaled overlays
  resubmitted, which the root tint now handles outright.
- The workspace boundary key remount stays, since it still repairs a stale
  surface after a workspace switch.

### Floating terminal window

- Enter and leave-full-screen events from the dedicated terminal window are
  forwarded to its renderer, and the narrowed terminal preload exposes the
  fullscreen state.
- The macOS traffic-light inset is dropped while the window is fullscreen and
  restored on exit, so the terminal header stops wasting the top strip.
